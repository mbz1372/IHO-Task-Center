# Supply OS V27 — Reliability, SLA, Evidence and Incident Response

## هدف
سیستم باید خرابی، منبع داده نامعتبر، کار بدون مسئول، بازماندن هشدار، عبور از SLA و توقف اجرای موتور پایش را آشکار کند؛ این قابلیت به‌معنای حذف همه رخدادهای پیش‌بینی‌نشده نیست.

## پیاده‌سازی و وضعیت واقعی
- `sco_control_sla_policy`: ساعت مهلت هشدار بحرانی/بالا/عادی با قابلیت اصلاح توسط مدیر.
- `sco_control_alerts`: مهلت، مسئول، تسک، آخرین ارجاع و سطح ارجاع.
- `sco_accept_control_alert_v27`: ثبت اتمیک تسک با مسئول فعال و مهلت معتبر؛ کلیک تکراری بدون تسک تکراری.
- `sco_control_alert_events`: تاریخچه ثبت، ارجاع و تأیید هشدار با RLS.
- `sco_control_watchdog_v27`: کنترل زمان‌بندی‌شده هر ساعت و تشدید هشدار تا سه سطح.
- `sco_control_scan_service`: بستن هشدار قطع بودن تأییدشده فقط با داده تازه بازگشت به حالت سالم؛ قطع شدن جریان داده به‌تنهایی به‌معنای رفع مشکل نیست.
- `sco_hotel_care_events`: تاریخچه مراقبت هتل، تغییر وضعیت و یادداشت مدیر.
- `sco_control_health_v27`: وضعیت ظاهری منابع پایش و میزان هشدارهای بدون تسک.
- `sco_cron_runs_v27`: خواندن **اجرای واقعی** از `cron.job_run_details`؛ تنظیم Job و اجرای دستی به‌جای اجرای موفق واقعی حساب نمی‌شود.
- `IncidentInbox`: صندوق هشدارها، فیلتر مهلت‌گذشته، ارجاع‌شده، فاقد تسک، ثبت واگذاری و تاریخچه.
- UI برای مدیر در بخش «رادار و اعتبار هتل‌ها»، برگه «صندوق هشدار و SLA» در Supply OS.

## فرکانس و سیاست پیش‌فرض
- پایش شبکه هتل: `0 4 * * *` یعنی روزانه ساعت 04:00 UTC.
- پایش عبور از SLA: `7 * * * *` یعنی ۷ دقیقه بعد از هر ساعت، UTC.
- SLA عادی: ۷۲ ساعت؛ مهم: ۲۴ ساعت؛ بحرانی: ۴ ساعت. قابل اصلاح توسط مدیر.
- سطوح ارجاع ۰ تا ۳؛ ارجاع فعلاً **درون‌سامانه‌ای و قابل ممیزی** است، نه پیامک یا ایمیل تضمین‌شده.

## نمونه سناریوهای آزمون عملیاتی قبل از پذیرش نهایی
| سناریو | معیار پذیرش |
|---|---|
| ورود کارشناس با Google بدون عضویت | عدم دسترسی به داده؛ نمایش انتظار تأیید، نه کد مدیر |
| کارشناس غیرفعال | عدم دسترسی به داده و امکان تغییر تسک |
| کارشناس دیگر | عدم توانایی ثبت نتیجه برای تسک فرد دیگر |
| دو کلیک هم‌زمان روی پذیرش یک هشدار | حداکثر یک تسک مرتبط؛ بدون دو نسخه موازی |
| قطع بودن نرخ با شاهد تازه | هشدار باز با مهلت و شدت مناسب |
| منقضی‌شدن شاهد نرخ | هشدار قطعی قبلی بدون شاهد تازه **بسته نشود** |
| بازگشت نرخ و ظرفیت به حالت صحیح با بررسی تازه | هشدار قطعی قابل بستن طبق قواعد تأییدشده |
| هتل فاقد مالک | هشدار، ورود به صف مدیر، واگذاری بعد از تأیید حساب واقعی |
| SQL Cron خاموش یا ناموفق | وضعیت سامانه هشدار «اجرای زمان‌بندی‌شده تأیید نشده» نشان دهد |
| تمام تسک‌ها Done ولی Provider قطع | پایش منبع باید جدا از تعداد تسک وضعیت خرابی را نشان دهد |
| خرابی همگام‌سازی رزرو/نرخ | عدم نمایش صفر جعلی؛ ثبت آخرین داده معتبر و منبع |
| رزرو API Out دارای مغایرت | ارجاع به مدیر؛ ممنوعیت تصمیم خودکار حساس |
| کارمند مسئول از تیم جدا شد | تسک‌های باز و مالکیت‌ها در صف جایگزینی |
| رزرو کنسل‌شده و برگشتی | محاسبه سود و شب اقامت با وضعیت نهایی رزرو و اصلاح حسابداری |
| ورود CSV دارای هتل مشابه | کشف و حل تطبیق با Hotel ID، جلوگیری از دوبل کردن |
| دو Provider برای یک هتل | یک پرونده هتل و چند قرارداد/نرخ/ظرفیت زیرمجموعه |
| اسکن تکراری | فقط یک هشدار باز برای نوع مسئله و هتل |
| تأخیر SLA | ارجاع مرحله‌ای همراه با ساعت و دلیل |
| قطعی اینترنت یا سرویس بیرونی | صف retry/backoff، وضعیت اتصال، بدون اعلام موفقیت کاذب |
| از دست‌رفتن دیتابیس | نسخه پشتیبان، بازیابی تمرین‌شده، RPO/RTO تعریف‌شده |

**مهم:** آزمون‌های بالا نقشه تست هستند و جز مواردی که مستقلاً ثبت شده‌اند، انجام کامل همه آن‌ها ادعا نشده است.

## وابستگی‌های حیاتی باقیمانده
1. فعال‌سازی حساب Google کارشناسان و انتساب واقعی مالکیت از متن قدیمی به `user_id`، با تأیید مدیر.
2. داده معتبر و تاریخ‌دار از API رزرو، نرخ، ظرفیت و Providerها، به تفکیک کانال B2C/B2B/API Out.
3. اتصال یکپارچه Confirm، Overbooking، شکایات و قراردادها.
4. محاسبه Importance Score و Supply Trust Score همراه با کیفیت و پوشش داده و مقایسه هم‌رده شهری.
5. اعلان قابل اتکا (پنل، پیامک یا کانال سازمانی)، retry و dead-letter queue.
6. داشبورد اثر تجاری اقدام کارشناس، KPI فروش/سود/شب اقامت و گزارش مدیرعامل.
7. آزمون چندکاربره، بار، امنیت RLS، بازیابی نسخه پشتیبان و تمرین Rollback واقعی.
8. اثبات نخستین اجرای زمان‌بندی‌شده از `cron.job_run_details`؛ تا آن زمان فقط Job فعال است.

## وضعیت پایگاه داده در زمان توسعه
- ۹٬۱۸۴ هتل، ۳٬۴۸۰ هتل در محدوده همکاری، ۴۳۰ هتل پیشران/کلیدی فاقد مالک سیستمی.
- ۴۳۰ هشدار فعال و ۴۳۰ SLA ثبت‌شده؛ هنوز هیچ‌کدام به تسک/کارشناس واگذار نشده‌اند.
- تنها یک عضو فعال و داده فروش معتبر کافی برای امتیازدهی موجود نیست؛ نمایش امتیاز نامعلوم صحیح است.
- تنظیم Cron موجود است، اما در لحظه آخرین بررسی `cron.job_run_details` هنوز اجرای **خودکار** ثبت نکرده بود.
